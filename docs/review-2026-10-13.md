# Review: Cursor support and the project as of db2585f

Review date: 2026-10-13. Scope: the four Cursor commits (`681272f..db2585f`,
1,375 lines across 25 files) plus a pass over the whole project. The Cursor
hooks documentation (cursor.com/docs/agent/hooks) was read to check the
adapter's assumptions.

The deterministic gate is green: 143 tests pass in-process and black-box,
`mypy --strict` and `ruff` are clean, 17 skills validate, and the corpus
passes 472/472 (Kiro and Cursor). Every defect below was found by a probe
that goes past what the suite checks. Each one cites its evidence.

## Improvements

- **I1 The mutation harness doesn't cover the Cursor code.**
  - `tests/mutate_guard.py` finds refusals of the form `return "<string>"`, but the Cursor binding refuses through tuples and `CursorHost.respond(...)`.
  - Its suites also exclude `test_hosts`.
  - I ran 7 hand mutants of `cursor.py`, `sessions.py`, and `hosts.py`: 6 were killed, and the TTL mutant (D8) survived. An 8th mutation failed to apply and doesn't count.
  - Fix: add those three files and `test_hosts` to the harness.
- **I2 The release test makes the suite slow.** `test_release` runs the whole suite again inside the extracted tree, which takes 40 s of the suite's 44 s wall time; the suite took 10 s at v0.5.0. A smoke subset in the extracted tree would prove the same thing.
- **I3 Use `subagentStart` for binding where it fires.**
  - Cursor now documents it with `subagent_id`, `subagent_type`, `task`, and `parent_conversation_id`. If `subagent_id` is the child's conversation ID, binding becomes exact and needs no transcript scraping.
  - That would fix D2 at the root, and it allows checking `subagent_type` against the order's role.
  - The README says it didn't fire in the CLI, so re-check in the IDE and keep transcripts as the fallback.
  - Until then, the fix for D2:
    - prefer the longest matching pending prompt;
    - refuse a Task prompt that names any *other* dispatched order.
  - Re-check, 2026-10-14: a throwaway git project installed logging hooks for
    `sessionStart`, `preToolUse`, `subagentStart`, and `subagentStop`, then
    launched a custom tool-using subagent twice. On Cursor Agent CLI
    2026.10.01-e373342 and 2026.10.14-0f9edde, the parent `Task` payload carried
    `conversation_id`, `tool_use_id`, and `tool_input` with `subagent_type`,
    `prompt`, `description`, and `run_in_background`; each child's `Shell` and
    `Read` payloads carried a distinct `conversation_id` equal to its
    `session_id` and `generation_id`, with `transcript_path: null`. Neither
    lifecycle hook fired. A configured `subagentStart` deny therefore never
    ran, and the child still created and read its marker. There is no
    `subagent_id` to correlate in the local CLI, so no binding change is safe;
    the transcript claim remains the fail-closed fallback.
- **I4 `merge_cursor_hooks` loses user config.** It silently drops hook entries that aren't lists from the user's `hooks.json`. It should refuse instead, as it does for a non-object `hooks`.
- **I5 Fix the D1 sandbox design, not just the mounts.**
  - The part worth protecting is the main checkout's *source*. Mount the project read-only, but mount `.surgical-team/`, `.git/`, `leases/`, and `cursor/` read-write.
  - Since v0.3, tampering with the ledger, the leases, or the bindings grants nothing beyond what the surgeon signed, so this keeps the guarantee that matters.
  - Test it by running `st draft`/`dispatch`/`report` inside a real container, not by checking argv.
- **I6 Stale docs.**
  - R11 in `docs/st-evolution.md` still says "Kiro-only hook format".
  - X-3's "makes the boundary real" claim is wrong; see D1.

## Suggested order

D1, D2, and D3 first: these are real breaks, and each has a probe that can
become a test. Then D4 (document it, and have `st doctor` and the copilot
prompt warn about cloud agents) and D5. Then I1 and I2, so the suite can
catch the next one. The rest after that.

## Audit (re-break probes, 2026-10-13)

Variants of each original attack were probed after the fixes: 24 probes
across D2, D3, D5, D6, D8, and D9, all with the expected verdict after D10.
They found one new defect, D10: blind checks were skipped when the event's
cwd was outside the ledger repo. It is fixed in c998f2c. One residual is
documented rather than fixed: Cursor binding trusts the transcript opening.
That opening is written only by Cursor and is guard-protected, so only the
surgeon pasting a pending briefing into a new chat could claim a dispatch.
